# CONTEXT.md — Onboarding-Flow Automation (Web + Android, operator-owned devices)

> Purpose: give a code reviewer with ZERO prior context everything needed to
> audit the engineering quality of this repository.

## 1. Purpose
A personal QA / workflow-enablement tool that automates the operator's OWN
end-to-end onboarding flow for a single Replit account per run:
1. Web registration via Playwright (Microsoft Edge).
2. Programmatic handling of the registration mailbox (1secmail disposable
   inbox, public REST API, no key required).
3. ADB-assisted UI walkthrough of the mobile onboarding screens on the
   operator's own Android phone, ending with logout and app close.
4. Back on PC: session refresh/login, then import of the operator's own
   GitHub repository.

## 2. Scope & Compliance Boundaries (read first — these are design constraints)
- Only the operator's own devices are involved (their PC, their phone).
- ONE account per run. No bulk or mass account creation; no account pools.
- The disposable inbox is a privacy choice for the registration mailbox.
  The service's own verification email is read through the inbox provider's
  public API — the standard email flow, never third-party mail interception.
- CAPTCHAs / anti-bot challenges: ALWAYS resolved manually by the operator.
  The code detects them, pauses, and waits. It never solves, bypasses, or
  circumvents CAPTCHAs, rate limits, or anti-bot systems.
- Credentials are generated locally and shown only in the operator's own
  console/state files. No credential harvesting of any kind.
- No identity spoofing, no ban evasion, no interaction with any account
  other than the one created in the same run.
- Reviewers: evaluate ENGINEERING QUALITY only (correctness, robustness,
  maintainability). If any code appears to violate the boundaries above,
  flag it as a BLOCKER with file:line citation.

## 3. Environment
- PC: Python 3.8+, Playwright (`channel="msedge"`), ADB in PATH, requests, colorama.
- Phone: operator's Android device, USB debugging enabled, Replit app installed
  (`com.replit.android`).
- Mailbox provider: 1secmail REST API (chosen because the originally preferred
  provider blocks datacenter IPs).

## 4. Workflow Specification (implementation must match)
### PC Phase A — Registration & mailbox confirmation
1. Generate mailbox address; fixed test password; username = local part.
2. Open signup page; dismiss third-party sign-in prompt if present.
3. Choose email registration; submit form.
4. Poll inbox for the service's confirmation message (sender/subject filter).
5. Extract the confirmation URL from plain-text or HTML body; unescape entities.
6. Open URL in browser; click the confirmation button; wait for success state.
### Android Phase B — Assisted onboarding (exact screen order)
1. Launch app → "Continue" → "Continue with Email".
2. Enter mailbox address → continue; enter password → "Login".
3. If an "invalid credentials" banner appears → tap "Login" once more.
4. Welcome screen → Continue; name screen → first name → Continue;
   username screen → Continue; role screen → "Developer" → Continue;
   source screen → "Google search" → Continue.
5. Main screen → "Skip"; subscription screen → "Skip".
6. Profile menu → scroll to "Log Out" → confirm → force-stop app.
### PC Phase C — Resume & import
1. Wait for session sync; reload browser; login if needed (or reuse saved
   session state).
2. Import the operator's GitHub repository.

## 5. File Inventory & Contracts
- `config.py` — constants: REPLIT_PASSWORD, REPLIT_PACKAGE_NAME,
  ANDROID_DEVICE_ID, EMAIL_CHECK_TIMEOUT, ANDROID_STEP_DELAY, PAGE_LOAD_TIMEOUT,
  LOGIN_RETRY_DELAY, ELEMENT_WAIT_TIMEOUT, TEMP_MAIL_PROVIDER, GITHUB_REPO_URL,
  DEBUG_MODE.
- `android_automation.py` — class `AndroidAutomation`: ADB wrapper
  (run_adb, tap, tap_pct, swipe_pct, type_text, press_key, hide_keyboard via
  keyevent 111, open_app, close_app, take_screenshot), uiautomator-based

  tap_text_or_pct), failure evidence (save_failure_evidence), and
  `complete_onboarding(email, password, username)`.
- `pc_automation.py` — class `PCAutomation`: Edge setup with storage_state,
  save_state, handle_captcha (manual-solve pause), create_account,
  verify_email(link), login_after_mobile, import_github_repo(url), close_browser.
- `main.py` — orchestrator: STAGES = [EMAIL, SIGNUP, VERIFY, ANDROID, PC_LOGIN,
  GITHUB, DONE]; checkpoint `state.json` (state["stage"] = next stage to run);
  per-stage recovery menu [r]etry/[m]anual/[s]kip/[q]uit; resume prompt.
- `requirements.txt`; runtime artifacts: state.json, auth_state.json,
  android_actions.log, ui.xml, screenshots.

## 6. Design Decisions
- ADB over a native Android app: single control point, faster iteration.
- uiautomator text-finding + percentage coordinates over hardcoded pixels:
  survives screen-size differences and keyboard-induced layout shifts.
- Checkpoint state machine: crash-safe resume; never recreates an account.
- Manual CAPTCHA pause: circumvention is explicitly out of scope (§2).
- Session persistence (storage_state) to avoid repeated logins.

## 7. Known File-Integrity Traps (reject matching files)
Chat-transfer corruption patterns seen in this project's history:
`def init(` instead of `def __init__(`; `if name == "main":` instead of
`if __name__ == "__main__":`; stripped indentation; comment lines without `#`;
trailing spaces inside string constants (`"EMAIL "`). Decoy duplicates to
ignore/delete: `main 2.py`, `Qwen_python_*.py`.
