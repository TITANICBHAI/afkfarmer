# 2. IMPORTANT DESIGN PRINCIPLE

Do not attempt to make automation "look human" through artificial behavior.

Do NOT implement:

```text
fingerprint spoofing
navigator property fabrication
proxy rotation for detection avoidance
CAPTCHA bypass
security-challenge bypass
device-attestation bypass
fake browser identity
randomized mouse trajectories intended to fool detection
randomized typing intended to fool detection
```

Instead, focus on:

```text
environment consistency
real browser/device configuration
observable application state
correct synchronization
bounded retries
rate-limit awareness
diagnostics
safe stopping
```

The goal is a clean, coherent automation environment rather than a detector-evasion system.

# 3. ENVIRONMENT INTEGRITY

The browser and Android environment should be internally consistent.

## Browser

Do not invent arbitrary values for:

```text
viewport
timezone
locale
device scale factor
hardware concurrency
device memory
```

Use values that correspond to the actual execution environment/configuration.

Do not inject fake `navigator.hardwareConcurrency` or `navigator.deviceMemory` values merely to appear more human.

If Patchright is used, configure it consistently and document the configuration.

## Network

Keep a single coherent network/session environment during one authorized run.

Do not rotate IPs during a session.

Do not add residential/mobile proxy infrastructure for the purpose of defeating reputation systems.

Do not make unsupported assumptions such as "all cloud/datacenter IPs are blocked."

If the service itself returns:

```text
rate limit
security challenge
access denied
account restriction
```

classify that explicitly rather than trying to circumvent it.

# 13. APPLICATION COOLDOWNS AND RATE LIMITS

Do not confuse application cooldowns with automation failures.

Examples:

```text
Please wait
Too many attempts
Try again later
Resend unavailable
Rate limited
```

These should become explicit states.

Correct pattern:

```text
detect cooldown
→ calculate remaining/waitable state if available
→ wait
→ re-check
```

Incorrect pattern:

```text
fixed 2-second sleep
→ click again
→ click again
→ click again
```

Never hammer an action simply because a fixed sleep elapsed.

---

# 14. RETRY POLICY

Retries must be state-specific.

Do not implement:

```python
if anything_fails:
    retry()
```

Instead:

```text
email not yet arrived
→ poll

page still loading
→ wait

temporary HTTP failure
→ bounded backoff

recoverable login error
→ documented retry

unknown UI
→ screenshot + diagnostic

security challenge
→ stop
```

Every retry loop must be bounded.
